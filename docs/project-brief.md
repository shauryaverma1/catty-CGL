# Project Brief — Purr & Petal

**Product:** A cute, cozy, academically accurate personal SSC CGL study website  
**Target exam cycle:** SSC CGL 2027  
**Deadline recorded in project handoff:** 31 October 2026  
**Status:** Early planning and seed-data stage; do not claim complete implementation.

## Product intent

Create a friendly study environment that makes syllabus navigation, bite-sized lessons, practice questions and revision feel approachable without sacrificing exam accuracy. The pastel visual identity is a presentation layer; academic evidence and clear approval states remain authoritative.

## Primary user

The project owner is a coding beginner. Implementation guidance and handoffs should be explicit, incremental and reproducible. Avoid silently choosing an unconfirmed framework, backend, hosting target or builder.

## Initial release strategy

Start with a narrow, verifiable pilot rather than broad, unreviewed content:
1. A syllabus explorer driven by stable topic IDs and parent-child relationships.
2. One small Tier-I General Intelligence & Reasoning — Analogies lesson.
3. Clear topic mapping and content-review states.
4. A responsive, accessible UI with a warm pastel visual system.
5. A simple way to identify stale, provisional, unresolved and approved materials.

## Out of scope until explicitly agreed

- Claiming 2027 syllabus coverage before the applicable official notice is checked.
- Publishing current-affairs lessons without a source and review/expiry policy.
- Cross-device sync (the project owner previously selected no sync).
- Broadly filling all syllabus topics with generated content before academic review.
- Pretending seed data, wireframes or starter scripts are a production-ready website.

## Decisions already recorded

- Builder: none selected/confirmed.
- GitHub account: available and connected.
- Cross-device sync: no.
- Access: public.
- Exam cycle: 2027.
- Design: pastel.

## Success criteria

- Every topic has a stable ID, parent where applicable, source reference and mapping status.
- The target cycle is visibly distinct from the source cycle.
- Lessons have a content approval state distinct from syllabus mapping status.
- Only reviewed and approved content can be labelled approved or published.
- The UI works on mobile and desktop, has semantic structure, keyboard navigation, visible focus states and readable contrast.
- A developer can run the documented data validation checks.
- Every known limitation and outstanding decision remains visible in the project documentation.
